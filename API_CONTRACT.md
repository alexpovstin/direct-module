# Контракт API v1

## HTTP

| Метод и путь | Вход |
| --- | --- |
| `POST /api/v1/commands` | JSON с полем `operation` и параметрами операции |
| `POST /api/v1/commands/text` | JSON `{"text":"Покажи расходы за неделю"}` |
| `GET /health` | Проверка доступности процесса без запроса к Яндексу |
| `GET /openapi.json` | Машиночитаемые схемы запросов |

Командные маршруты требуют `Authorization: Bearer <DIRECT_MODULE_API_KEY>` и явных разрешений получателю `interface`. Локальная консоль вызывает `/api/v1/admin/commands` и `/api/v1/admin/commands/text` с разрешениями получателя `local`. Панель использует однодоменные запросы к loopback с заголовком `X-Direct-Module: local-admin`.

## Операции

| `operation` | Поля верхнего уровня | Разрешение и результат |
| --- | --- | --- |
| `list_organizations` | Нет | Одно разрешение на весь каталог. `data.organizations` с `id`, `name`, `aliases`, `website` |
| `list_accounts` | Опционально `organization_id` | Одно разрешение на весь каталог. `data.accounts` с привязками рекламных аккаунтов |
| `check_connection` | `connection_id` | Разрешение на подключение. `data.connection` с результатом проверки, типом и подтверждённым логином |
| `discover_accounts` | `connection_id`, опционально `login` | Разрешение на подключение. `data.mode` и `data.accounts` с найденными логинами. Операция выполняет поиск без сохранения найденных аккаунтов |
| `get_balance` | Опционально `account_id` или `organization_id` | Разрешение на каждый аккаунт. `data.accounts[]` содержит `balance` и `diagnostics` |
| `get_spending` | Опционально `account_id` или `organization_id`, `date_from`, `date_to`, `vat` | Разрешение на каждый аккаунт. `data.accounts[]` содержит `spending` и `diagnostics` |
| `get_financial_summary` | Опционально `account_id` или `organization_id` | Разрешение на сводку каждого аккаунта и дополнительные разрешения на баланс и расходы. `data.accounts[]` содержит суточные показатели и прогноз |

ID каталога — положительные локальные целые числа. В одном финансовом запросе указывайте `account_id` или `organization_id`. Без них операция применяется ко всем аккаунтам с выданным разрешением на эту операцию. В выборке организации возвращаются только её аккаунты с соответствующим разрешением. Если требуемое разрешение на сводку есть, но доступен лишь один показатель, сводка возвращается частично.

`date_from` и `date_to` задаются вместе в формате YYYY-MM-DD. Границы включаются, максимальная длина — 366 завершённых дней. Период по умолчанию — семь дней, включая вчера. `vat` принимает `excluded` или `included`, по умолчанию `excluded`. Для сводки НДС отчёта выбирается по настройке баланса. Даты отчёта трактуются по Москве.

```json
{"operation":"get_spending","organization_id":1,"vat":"excluded"}
```

## Ответы

Успешное выполнение возвращает HTTP 200 и объект `{"operation":"…","data":{…}}`. Финансовый ответ по аккаунту содержит `account`, `organization_name`, `connection_status` и `diagnostics` с ключами `balance` и `spending` при наличии соответствующих ошибок. Вместо недоступного показателя возвращается `null`. Возможен HTTP 200 с диагностикой по каждому аккаунту.

`balance` содержит `amount`, `currency`, `vat`, `shared_account_id`, `updated_at`. Значение `vat` для баланса может быть `unknown`.

`spending` содержит `date_from`, `date_to`, `total`, `daily` (объект с датами в качестве ключей), `currency`, `vat`, `updated_at`.

Сводка добавляет `spending_yesterday`, `spending_7_days`, `average_daily_spending`, `forecast_days`, `forecast_reason`, `currency`, `date_from`, `date_to`, `updated_at`, `connection_diagnostic`. Валюту каждого значения определяет его собственный объект `balance` или `spending`. Денежные числа и дни передаются десятичными строками. Метки обновления — ISO 8601 в UTC. `connection_status` отражает последнюю явную проверку подключения и принимает `unchecked`, `authorized` или `error`.

Ошибка команды до обработки аккаунтов имеет вид

```json
{"error":{"code":"permission_denied","message":"Выдайте разрешение в одноимённом разделе."}}
```

Та же структура диагностики используется в финансовых строках. По ситуации объект содержит `yandex_code` или `retry_after_seconds`. Основные статусы команд — 401 при неверном ключе, 403 при отказе в доступе, 404 для неизвестной записи, 422 для некорректного запроса, 502–504 при проблемах внешнего API или хранилища. Коды диагностики в финансовых строках позволяют обработать `yandex_access_denied`, `managed_balance_unavailable`, `no_shared_account`, `ambiguous_shared_account` и `report_pending` по-разному.

## Поддерживаемый текст

```json
{"text":"Проверь баланс организации Альфа"}
```

- «Проверь баланс организации Альфа» ищет название или псевдоним Альфа без учёта регистра.
- «Сколько денег осталось у всех клиентов?» запрашивает балансы всех разрешённых аккаунтов.
- «На сколько дней хватит рекламного бюджета?» запрашивает финансовую сводку.
- «Покажи расходы за неделю» запрашивает последние семь завершённых дней.
- «Покажи расходы за вчера», «Покажи организации» и «Покажи аккаунты» выполняют соответствующие операции.

Неоднозначные названия возвращают `ambiguous_organization`, неизвестная фраза возвращает `unknown_command`.
