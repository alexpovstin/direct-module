# Статус direct-module 0.1.0

## Реализовано

- Панель с семью разделами, включая финансовую сводку, настройку организаций и аккаунтов, разрешения, журнал и консоль команд.
- REST API v1 с семью операциями, отдельным ключом центрального интерфейса и детерминированным разбором текста на русском.
- Адаптеры Яндекс Директа v5 и Live 4, поиск клиентов агентства, проверка логина и чтение финансов с диагностикой доступности.
- Шифрование OAuth-токенов, разрешения на чтение по умолчанию закрыты, история финансов и операций в SQLite, начальная миграция Alembic.

## Проверено 25 ноября 2026 года

- Windows и Python 3.12.14. Сервер запустился через CLI на `127.0.0.1`. Панель и `/health` ответили по HTTP.
- Миграция `0001` прошла в обе стороны на пустой базе. `alembic check` подтвердил соответствие схемы моделям.
- Все 13 тестов Pytest прошли на временной SQLite с имитацией ответов Яндекса.
- В Chrome проверены добавление организации, ввод токена с Windows DPAPI, выдача разрешений, авторизация, добавление и привязка аккаунта, получение сводки, прогноз, ошибка Live 4 при доступных расходах, текстовая команда и журнал. Ответы Яндекса в браузерном сценарии имитировались.

## Проверка на реальных данных

На пилотном клиентском аккаунте агентства проверены авторизация, чтение расходов и баланса общего счёта. Live 4 может вернуть подтверждённый логин токена, который отличается от логина главного представителя. Модуль учитывает оба логина при проверке счёта.

В Chrome проверены переименование подключения, определение типа аккаунта, выбор организации и настройки НДС, пакет разрешений, текстовая команда и сохранение диагностики после перезагрузки. Прошли 17 тестов Pytest и `alembic check`.

Порядок запуска и первого подключения описан в [README](README.md).

## Следующий этап — статистика

1. Добавить экран «Статистика». Выбор аккаунта и дат, быстрые периоды «Вчера» и «7 дней», выбор метрик в таблице по дням. Первые колонки — показы, клики, расходы и конверсии. Если под просмотрами нужны просмотры видео, предусмотреть отдельные метрики для поддерживаемых форматов. [Поля Reports](https://yandex.ru/dev/direct/doc/ru/fields-list), [значения полей](https://yandex.ru/dev/direct/doc/ru/report-format)
2. Согласовать цели для отчёта и модель атрибуции, сравнить выборку за один день и одну неделю с кабинетом Директа. Разрез по выбранным целям запрашивать через `Goals` в Reports. Общие конверсии и разрезы по целям показывать раздельно. Для этого этапа достаточно данных Директа. [Цели и модели атрибуции в Reports](https://yandex.ru/dev/direct/doc/ru/spec)
3. Хранить дневные строки в SQLite с ключом по аккаунту, дате и параметрам отчёта, включая цели, атрибуцию, валюту и НДС. После полного успешного ответа заменять строки выбранного периода одной транзакцией. Каждый день обновлять три последних завершённых дня. Для корректировок более старых дат использовать `Changes.check` с `BorderDate` либо `DateRangeType: AUTO`. Регистрировать изменившиеся значения, время выгрузки и отчёты, которых коснулась корректировка. [Актуальность статистики](https://yandex.ru/dev/direct/doc/ru/actual)
4. Собрать недельный отчёт по расходам и конверсиям за завершённую неделю по Москве. Показывать выбранные цели, валюту, НДС и дату выгрузки. Если данные изменились после выгрузки, показать уведомление с прежним и новым значениями. Проверить один отчёт вручную, затем настроить регулярное формирование. Отдельное сравнение с API Метрики запланировать после проверки показателей Директа.

## Импорт организаций

Подойдёт ссылка Google Sheets с доступом «Читатель» и названием вкладки. Если доступ по ссылке ограничен, приложите XLSX или CSV в UTF-8 с нужной вкладкой. Для импорта достаточно столбца «Название». При наличии возьмём «Сайт», «Псевдонимы» и «Логин Директа». Сначала сверим поля, покажем новые записи и совпадения с текущим каталогом, затем импортируем согласованные строки.
