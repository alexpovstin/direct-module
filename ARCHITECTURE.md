# Архитектура direct-module

## План реализации

1. Разделить каталог, разрешения, финансовую историю и журнал операций в SQLite, управлять схемой через Alembic.
2. Вынести версию 5 и Live 4 в отдельные адаптеры. Преобразовывать ошибки Яндекса в локальные диагностические коды.
3. Направить структурированные и текстовые команды в единый исполнитель. Проверять разрешения непосредственно перед чтением. Хранить успешные финансовые наблюдения.
4. Добавить локальную панель и версионированный контракт для «Интерфейса». Проверить сценарий подключения и частичные ошибки с подменёнными HTTP-ответами.

## Данные

| Таблица | Назначение |
| --- | --- |
| `organizations` | Название, текстовые псевдонимы и сайт |
| `connections` | Название, предполагаемый тип подключения, шифротекст токена и результаты последней проверки |
| `accounts` | Подтверждённая привязка к подключению, Yandex ClientId, логин, организация, настройки общего счёта и НДС |
| `permissions` | Явное разрешение операции для получателя и цели |
| `financial_history` | Последовательность полученных балансов и отчётов с периодом, валютой, НДС и временем чтения |
| `operation_log` | Время, операция, источник, ID цели, результат и безопасный код ошибки |

Подключение может обслуживать несколько аккаунтов. Организация может объединять аккаунты разных подключений. Внутри подключения логин и `ClientId` уникальны. Один аккаунт привязывается к одной организации либо остаётся без привязки. Финансовые команды возвращают показатели по каждому аккаунту.

## Привязки и методы Яндекса

| Сценарий | Что проверяет модуль |
| --- | --- |
| Свой аккаунт | `Clients.get` без `Client-Login` определяет рекламодателя. Баланс запрашивается у Live 4, расходы через Reports |
| Клиент агентства со своим токеном | `Clients.get` определяет `SUBCLIENT`. Чтение идёт от имени этого рекламодателя в пределах его прав |
| Подключение агентства | `Clients.get` подтверждает тип `AGENCY`. Затем `AgencyClients.get` выполняет постраничный поиск без `Client-Login`. Привязка, проверка и Reports используют логин клиента |
| Управляющее подключение | Для известного подопечного `Clients.get` должен вернуть указанный логин и отдельный `ClientId`. Отчёт дополнительно зависит от результата запроса к Reports. При отсутствии доступа к общему счёту можно подключить токен рекламодателя |

Адаптер v5 использует опубликованные адреса JSON `/json/v501/clients`, `/json/v501/agencyclients` и `/json/v501/reports`. Для баланса Live 4 отправляет `AccountManagement` с `Action: Get` на `/live/v4/json/`. Для агентства указывается логин владельца общего счёта либо выбранный `AccountID`. Для собственного подключения выбирается счёт, принадлежащий подтверждённому владельцу. При нескольких совпадениях модуль запрашивает ID счёта. Контракт Live 4 описывает чтение собственного счёта и счёта клиента агентства. Для подопечного управляющего подключения модуль возвращает `managed_balance_unavailable`. [Роли и доступы](https://yandex.ru/dev/direct/doc/ru/objects/roles), [Clients.get](https://yandex.ru/dev/direct/doc/ru/clients/get), [AgencyClients.get](https://yandex.ru/dev/direct/doc/ru/agencyclients/get), [сервис Reports](https://yandex.ru/dev/direct/doc/ru/reports), [формат Live 4](https://yandex.ru/dev/direct/doc/dg-v4/ru/concepts/JSON), [AccountManagement Get](https://yandex.ru/dev/direct/doc/dg-v4/ru/live/AccountManagement_Get), [управляющие аккаунты](https://yandex.ru/support/direct/ru/campaigns/mcc)

## Финансовые расчёты

- Сводка охватывает семь завершённых дней по Москве. Показатель «Вчера» берётся из этого же отчёта. Яндекс может уточнять статистику после окончания дня. [Актуальность статистики](https://yandex.ru/dev/direct/doc/ru/actual), [часовой пояс статистики](https://yandex.ru/support/direct/ru/efficiency/timetargeting)
- Расход читается из полей `Date` и `Cost` отчёта `ACCOUNT_PERFORMANCE_REPORT`. Сумма переводится из миллионных единиц валюты в денежные единицы. Валюту подтверждает `Clients.get`. В успешно сформированном полном отчёте день без строки учитывается как день без расходов. Если в строке отсутствует числовое значение и Яндекс передал `--`, сумма за период считается неопределённой. Ошибка отчёта возвращается отдельно от числовых показателей. [Допустимые поля](https://yandex.ru/dev/direct/doc/ru/fields-list), [заголовки Reports](https://yandex.ru/dev/direct/doc/ru/headers), [валюта отчёта](https://yandex.ru/dev/direct/doc/ru/concepts/stat)
- Баланс сохраняется как `Amount` в валюте общего счёта. Тип учёта НДС для этого числа оператор подтверждает в настройках аккаунта. До подтверждения модуль показывает баланс и расходы отдельно, отчёт запрашивается без НДС. После подтверждения сводка запрашивает расходы на той же основе. [Баланс общего счёта](https://yandex.ru/dev/direct/doc/dg-v4/ru/live/AccountManagement_Get), [НДС в Директе](https://yandex.ru/support/direct/ru/payments/faq), [IncludeVAT](https://yandex.ru/dev/direct/doc/ru/spec)
- Среднесуточный расход равен сумме за семь дней, делённой на семь. При положительном среднем расходе, одинаковой валюте и подтверждённом учёте НДС прогноз равен балансу, делённому на среднесуточный расход. Отрицательное число означает, что баланс уже исчерпан. Отсутствующий баланс хранится как отсутствие наблюдения и отображается прочерком с диагностикой. Успешное чтение баланса в 0 сохраняется.
- Reports использует автоматический режим. При `201` и `202` запрос повторяется с прежними параметрами согласно `retryIn` в пределах двух повторов и пяти секунд ожидания между запросами. Длительное ожидание возвращает `report_pending`. [Онлайн- и офлайн-отчёты](https://yandex.ru/dev/direct/doc/ru/mode)

## Границы компонентов

FastAPI обслуживает локальную панель и REST. Исполнитель повторно подтверждает идентичность рекламного аккаунта перед чтением, проверяет разрешения, записывает результат. Панель загружает сохранённые разрешённые наблюдения из SQLite и запрашивает свежие данные по кнопке. Метки времени обновления сохраняются отдельно для баланса и отчёта.

Детерминированный интерпретатор получает текст, дату и индекс доступных названий организаций. Он возвращает структурированную команду. Через фабрику приложения можно передать другую реализацию интерфейса `Interpreter`. Исполнитель повторно валидирует результат интерпретации и проверяет те же разрешения. Распознавание речи и передача команд от голосовых каналов остаются в центральном проекте.

Диагностика неудачного финансового чтения сохраняется в истории отдельно от числовых наблюдений. Сводка после перезагрузки показывает результат последней попытки для текущих параметров, включая причину недоступности показателя. Пакет разрешений применяется одной транзакцией.

Интерфейс `SecretStore` отделяет шифрование от SQLite и сетевого транспорта. На Windows используется DPAPI текущего пользователя или Fernet с явно заданным ключом. Для Linux подходит Fernet с внешней подачей ключа. Токен расшифровывается при обращении к Яндексу. Сырые ответы с ошибками Яндекса и текст команд в журнал не сохраняются.
